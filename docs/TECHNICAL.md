# ICN 특가 레이더 · 기술 문서

수집 규칙, 정확도 검증, 데이터 출처의 세부 내용입니다. 일반 소개는 [README](../README.md)를 보세요.

인천 출발 항공권·국내선·호텔 숙박 할인 행사를 뉴스 기사에서 모아 **예고 / 진행중 / 날짜 미상 / 마감**으로 보여주는 개인 프로젝트.

- 화면: https://theddack.github.io/icn-air-deals/
- 수집: Google Apps Script가 하루 4회(KST 09·13·18·22시 17분 전후 ±15분) GitHub Actions `collect`를 실행 → `data/deals.json` 커밋 → GitHub Pages 배포. Actions 자체 예약은 2~5시간 늦고 하루 1회꼴로 빠져서(2026-10-25~29 기록) 비상용으로만 둡니다. 트리거 코드는 `scripts/apps_script_trigger.gs` (토큰은 Apps Script 스크립트 속성 `GITHUB_TOKEN`에만, 저장소 `icn-air-deals` 한정 Actions 읽기·쓰기 권한)

## 알려진 한계 (먼저 읽기)

- **뉴스 기사 제목만 봅니다.** 판매 기간·할인율·출발지는 제목에서 자동으로 뽑아서 틀릴 수 있습니다. 예약 전에 항공사 공지를 확인하세요.
- **"출발지 미확인"이 대부분입니다.** "인천 출발"은 제목에 `인천~X`, `인천-X`, `인천발`, `인천 출발` 같은 노선·출발 근거가 있을 때만 붙고, "인천공항" 같은 단순 언급으로는 붙지 않습니다. "인천 외 출발 숨기기"는 김포·김해·부산·청주 등 다른 출발지나 국내선이 명시된 것만 숨깁니다.
- **탑승 기간은 제목에 있을 때만 채워집니다.** 2026-10-15 표본 기준 탑승 기간이 적힌 제목은 123건 중 4건입니다.
- **기사 묶기는 규칙 기반입니다.** 사람이 정답을 단 실제 기사 123건(`tests/fixtures/labeled_2026-10-15.json`)에서 잘못 합침 0건, 잘못 나눔 1건(핀에어 얼리버드)입니다. 이 표본 밖에서는 같은 항공사가 이틀 안에 행사명·날짜·할인율 없이 서로 다른 행사를 내면 하나로 묶일 수 있습니다.
- **여러 항공사가 나오는 기사**는 특가 표현이 있는 절의 항공사가 하나로 정해질 때만 그 항공사로 분류하고, 아니면 "항공사 미분류"로 따로 보여줍니다 (예: "이스타·에어프레미아, 연중 최대 프로모션").
- **국내선 탭은 비어 있는 날이 많습니다.** 제목에 `국내선`, `김포~제주`, `제주행` 같은 노선 표현이 있고 국제선이 섞이지 않은 항공 기사만 국내선으로 봅니다. 2026-10-15 기준 최근 30일 기사 중 해당하는 것은 0건이었습니다(진에어 추석 할인은 "국제선 43개 노선·국내 역귀성"이라 국제선으로 분류).
- **호텔·숙박**은 `collector/hotels.py`의 브랜드 26곳(호텔·리조트, 예약 플랫폼·여행사, 숙박세일 페스타)이 제목에 있고 숙박 맥락(호텔·숙소·객실 등)과 할인 표현이 함께 있을 때만 모읍니다. 뷔페·침구·골프처럼 숙박이 아닌 할인은 뺍니다. 라벨 표본 63건(`tests/fixtures/labeled_hotels_2026-10-15.json`)에서 잘못 합침 0건, 잘못 나눔 3건(숙박세일 페스타가 판매처별 할인액이 달라 4묶음)입니다.
- **노선(출발 → 도착)은 제목에 `인천~구마모토`, `세부행`, `인천발` 같은 표현이 있을 때만** 채웁니다. 공항이 여럿인 도시(도쿄·방콕 등)와 나라 이름은 공항 코드를 붙이지 않습니다. 한 행사가 여러 노선을 다루면 목록으로 보여줍니다.
- **필드별 근거**: 판매 기간·탑승 기간·할인·노선 옆의 "근거"는 그 값을 뽑은 기사 링크입니다. 같은 행사 기사끼리 탑승(투숙) 기간이 다르면 하나를 고르지 않고 "출처 간 불일치"로 표시합니다.
- **해외 호텔은 시범(2026-10-15~)**: 국내 기사 중 해외 지명이 나온 숙박 할인(브랜드가 없으면 "브랜드 미확인", 업계 동향 기사 제외)과, 영어판 Google 뉴스에서 가격 할인(% off·할인 코드 등)이 분명한 제목만 모읍니다. 포인트 적립·포인트 숙박·매각·인사·박람회·할인 코드 모음 페이지는 뺍니다. **영어 기사는 번역하지 않고** 제목 원문을 보여주며 할인율·기간·지역만 규칙으로 뽑습니다. 첫 수집에서 해외 후보 12건을 직접 읽어 오탐 6건(코드 모음 3, 포인트 숙박 1, 박람회 1, 동향 기사 1)과 잘못 합침 1건을 규칙으로 막았고 남은 6건은 모두 실제 할인입니다. 화면에는 "시범"으로 표시합니다.
- **언론사 RSS는 피드마다 최근 50~100건**만 있어서, 하루 4회 받으며 쌓여야 효과가 납니다. 2026-10-15 첫 실행에서는 1,160건 중 행사 기사 2건에 요약 사실값 9개가 붙었고(원문 대조 오류 0), 항공 행사 판매 기간 미확인이 15/20 → 13/20이 됐습니다.
- **판정 규칙 보완(2026-10-15)**: '할인 프로모션'·'출발편 할인'·'공동 프로모션'처럼 노선·운임 단어가 없어도 운임 할인인 표현을 받습니다. 멤버십·마일리지·수하물·기내·팝업·환승 혜택은 뺍니다. 후보 1,263건 비교에서 기존 수집분 누락 0, 새로 수집 12건(오탐 0, 모두 기존 행사에 정상 병합, 1건은 어느 행사인지 판단 보류), 라벨 표본 잘못 합침 0·잘못 나눔 1(변경 전과 동일).
- **Google 뉴스 RSS는 검색어당 최대 100건**만 줍니다. 기사가 많은 항공사는 일부가 빠질 수 있습니다.
- 공개 레포의 예약 실행(schedule) 워크플로는 레포 활동이 60일 없으면 GitHub가 자동으로 끕니다.

## 수집 방식

| 대상 | 방법 |
|---|---|
| 국내 11개 + 해외 43개 항공사 (`collector/airlines.py`) | Google 뉴스 RSS 검색: `"항공사명" (특가 OR 프로모션 OR 할인 OR 세일) when:30d` |
| 항공사 미지정 기사 | `인천 출발 항공권 특가`, `항공권 프로모션 국제선`, `국내선 항공권 특가`, `김포 제주 항공권 할인` 검색 후 제목에서 항공사 판별 |
| 언론사 자체 RSS 28곳 + 문체부 보도자료 RSS (`collector/sources/outlet_rss.py`) | 기사 요약문에서 판매·탑승 기간, 할인, 노선을 뽑아 **제목에서 못 뽑은 값만** 채움. 같은 제목의 기사에 붙이고, 처음 보는 행사 기사면 새로 더함. robots.txt가 막은 곳(머니투데이·파이낸셜뉴스·헤럴드경제)은 제외. **요약문 원문은 저장하지 않고** 뽑은 값, 60자 이하 근거 구절, 원문 주소만 저장 |
| 호텔·숙박 26곳 (`collector/hotels.py`) | `"브랜드" (특가 OR 할인 OR 세일 OR 프로모션 OR 쿠폰) when:30d` |
| 땡처리닷컴 판매가 (`collector/ttang.py`, `data/ttang.json`) | 판매 목록 한 페이지를 하루 1번. robots.txt는 이 경로를 막지 않고, 약관은 '영리목적 이용'만 금지. 인천 출발만 골라 도착지·항공사·직항 여부·여정·출발 기간·표시 총액을 저장하고 매일 통째로 바꿈. 화면은 도착지별 최저 총액과 목록 링크 |
| Secret Flying 서울 출발 특가 (`collector/secretflying.py`, `data/secretflying.json`) | 서울 특가 목록 한 페이지를 하루 1번(robots.txt Crawl-delay 1, 공개 RSS 없음). 회원 전용 카드는 건너뛰고 공개 제목에서 도착지·가격·통화·왕복/편도만 뽑아 게시물 링크와 함께 저장. 14일 동안 목록에 다시 안 보이면 뺌 |

항공사 공식 사이트는 수집하지 않습니다. **이 프로젝트는 봇 차단을 우회하지 않고, 브라우저인 척하는 User-Agent도 쓰지 않습니다.** 2026-10-15에 봇임을 밝힌 요청(`icn-air-deals/0.1`)으로 확인한 결과:

| 항공사 | 결과 |
|---|---|
| 진에어·에어부산·에어서울·에어프레미아·트리니티(티웨이)·대한항공 | Cloudflare·Akamai 차단 (403) |
| 아시아나 | robots.txt는 `/event/` 허용, 서버는 봇 User-Agent 연결을 끊음 (HTTP/2 스트림 오류) |
| 제주항공 | 봇 User-Agent는 첫 화면부터 403 |
| 이스타항공 | 접근은 되지만 이벤트 목록을 내부 JSON-RPC로만 불러옴. 화면 HTML에 목록이 없음 |

그래서 행사 카드의 "공식 페이지에서 확인"은 항공사 홈페이지(아시아나·이스타는 이벤트 목록) **링크**일 뿐이고, 모든 행사의 검증 상태는 "뉴스 기반 · 미확인"입니다. 공식 이벤트를 수집할 수 있게 되면 `verification: "official"`로 표시합니다.

## 출발 시간표 (인천공항 공공데이터)

`collector/flights.py` → `data/flights.json`. 공공데이터포털 인천국제공항공사 API 두 개를 씁니다. 키는 레포 Secrets `DATA_GO_KR_KEY`에만 있고 공개 파일에 넣지 않습니다. 키가 없거나 API가 실패하면 시간표만 건너뛰고 행사 수집·배포는 계속합니다.

| API | 쓰는 것 | 2026-10-15 실제 응답으로 확인한 범위 |
|---|---|---|
| 여객기 정기운항편 일정 (`PaxFltSched/getPaxFltSchedDepartures`) | 편명·항공사·출발 예정 시각·도착 공항·운항 기간·요일 | 하계 시즌(S26) 1,783편. 1,145편이 10/24에 끝나고 10/25 이후는 45편(최대 12/5)뿐. 동계 일정은 아직 없음. 도착 시각 필드 없음. 날짜·공항 파라미터는 무시되고 전체가 옴 |
| 항공기 운항 현황 상세 (`statusOfAllFltDeOdp/getFltDeparturesDeOdp`) | 변경 시각·상태(출발·지연 등)·공동운항 | 3일 전 ~ 6일 뒤 |

- **날짜 상태 3단계**: 시간표 확보(정기편 대부분의 종료일까지) / 일부만 확보(다음 시즌 일정 미공개, 공개된 일부 편만) / 미확보. 확보된 날짜에 편이 없으면 "운항편 없음", 나머지는 "운항편이 없다는 뜻이 아님"을 표시합니다.
- **공동운항**: 한 줄 = 실제 운항편. 공동운항 판매 편명(예: KE5721)은 실제 운항편(OZ112) 아래에 붙이고, 판매 편명으로도 검색됩니다. 운항 현황에 한 번도 나오지 않은 편은 "공동운항 여부 미확인"입니다.
- **행사 연결** (할인 적용 여부는 표시하지 않음 — 실제 할인가를 확인하지 않으므로):
  - *노선 일치 행사*: 운항 항공사(편명 IATA 코드) + 행사 노선의 출발지 인천 + 도착지가 모두 기사로 확인되고, 탑승 기간을 알면 그 안
  - *항공사 진행 행사*: 운항 또는 판매 항공사만 같은 행사 (노선이 다르거나 확인되지 않음). 접어서 보여줍니다
- **행사 카드의 "인천 출발 운항 도착지"**: 행사를 낸 항공사(IATA 코드)가 앞으로 7일간(확보된 시간표 안) 인천에서 직접 운항하는 도착지와 편수. 기사에서 인천 출발 노선이 확인된 도착지는 "행사 대상 확인"으로 표시합니다. **좌석이 남았는지·할인가는 공개 데이터에 없어서 표시하지 않습니다.**

## 처리 순서

1. **수집**: 검색어별 RSS (`collector/sources/news_rss.py`). 검색어 하나 실패해도 나머지는 계속, 전부 실패하면 데이터를 덮어쓰지 않음
2. **거르기**: 퀴즈·주가·실적·기내식·마일리지 적립 기사 제외, "할인/프로모션"은 항공권 맥락(노선·운임·%) 있을 때만 (`collector/extract.py`)
3. **추출**: 항공사, 판매 시작·마감일("13일부터", "내일부터", "14일부터 20일까지", "나흘간", "12월 31일까지 탑승"은 제외 등), 할인 표기, 인천 출발 여부, 따옴표 속 행사명
4. **묶기**: 행사명 → 날짜 → 행사명 포함 → 할인율 → 제목 단어 → 이틀 내 보도 순 (`collector/merge.py`)
5. **신규 표시**: 처음 본 지 48시간 안이면 "신규", 기존 행사에 기사가 더해졌으면 "기사 추가". 첫 수집분(`baseline_first_seen`)은 신규로 보지 않음
6. **수집 상태**: 마지막 수집이 12시간보다 오래됐거나 실패한 검색어가 있으면 화면 위에 경고
7. **상태**: KST 오늘 기준 (`collector/status.py`, 화면 `site/app.js`도 같은 규칙). 마감 7일 후 목록에서 내림. 마감일을 모르는 행사는 마지막 기사 14일 후 "진행 여부 미확인"으로 목록 아래에 접고, 할인율·탑승 기간·행사명·노선 중 하나라도 있으면 30일까지 보관(없으면 14일에 내림)

|---|---|
| 오전 09~13시 | 오늘 판매 시작 · 곧 시작(판매 시작 2~3일 전) · 오늘 마감 · 새로 발견 |
| 오후 13~18시 | 새로 발견 · 오늘 판매 시작 · 오늘 마감 |
| 저녁 18~21시 | 오늘·내일 마감 · 내일 판매 시작 · 오늘 판매 시작 · 새로 발견 |

- **실행 시점**: 수집 작업이 끝날 때마다. 수집 회차(09·13·18시 17분 전후)를 오전·오후·저녁 시간대 안에 두어 수집이 끝나자마자 그 시간대 알림이 나갑니다(22시 회차는 데이터만 갱신). 예약(09:07·14:07·18:37·20:07)은 비상용입니다. 앞 시간대가 보내지 못했으면 그 시간대 종류도 다음 실행에서 함께 보냅니다
- **중복 방지**: 행사마다 알림 종류별 발송일을 `data/telegram_sent.json`에 남깁니다. 기사가 더해져 행사 id가 바뀌면 같은 기사를 함께 담고 있을 때 같은 행사로 봅니다. 기사가 겹치지 않으면 주인·판매 시작일·종료일이 모두 같고 행사명·도착지가 같아야 하며, 날짜가 둘 다 없으면 최근 기사 날짜가 14일 안이어야 합니다(없음끼리 같다고 치면 한 달 뒤 같은 이름의 다른 회차가 합쳐짐). 양쪽 날짜가 다르면 다른 행사입니다. 메시지가 여러 통으로 나뉘어 중간에 실패해도 보낸 항목은 기록하고 남은 항목만 다음 실행에서 보냅니다. 기록은 저장소에 올리고(거절되면 원격을 다시 받아 5번까지 재시도) Actions 캐시에도 남겨, 저장소에 못 올린 경우에도 다음 실행이 최신 기록(`saved_at`)을 씁니다
- **출처 표시**: 항공사 공식 · 판매처 공식 · 기사 기준. 기사 건수는 표시하지 않습니다
- **수집 문제**: 행사 데이터가 14시간보다 오래되면 신규 알림을 보내지 않습니다. 수집 실패·오래된 데이터 경고는 여행 알림에 넣지 않고 Actions 로그와 관리자 대화(`TELEGRAM_ADMIN_CHAT_ID`, 선택)로만 보냅니다
- **미리 보기**: `python -m collector.notify --dry-run --now 2026-10-27T09:30` (보내지 않고 기록도 바꾸지 않음). Actions에서 `telegram`을 손으로 실행하면 기본이 dry-run입니다
- 비밀값: `TELEGRAM_BOT_TOKEN`(봇 토큰), `TELEGRAM_CHAT_ID`(받는 사람 chat id, 여럿이면 쉼표로). 없으면 알림을 건너뜁니다
- 받는 사람이 여럿이면 동시에 보냅니다. 한 사람에게 실패해도(번호 오류·봇 차단) 다른 사람은 그대로 받고, 실패한 사람은 TELEGRAM_CHAT_ID 안의 순번만 로그에 경고로 남깁니다. 모두 실패했을 때만 다음 실행에서 다시 보냅니다
- 받는 사람 추가: 그 사람이 봇(https://t.me/icn_air_deals_bot)에서 시작을 누르고 아무 글이나 보냄 → Actions에서 `telegram-whoami`를 손으로 실행하면 봇이 그 사람에게 chat id를 답장 → `TELEGRAM_CHAT_ID`를 `기존id,새id`로 다시 저장. 봇은 최근 24시간 안에 받은 메시지만 볼 수 있습니다

기사는 `data/articles.json`에 45일간 보관하고, 매 실행마다 저장된 기사 전체를 다시 추출·묶기 때문에 규칙을 고치면 지난 기사에도 반영됩니다.

## 로컬 실행

Python 3.11+ 표준 라이브러리만 씁니다.

```sh
python3 -m unittest -v          # 테스트 (실제 기사 제목 기반)
python3 -m collector.main       # 수집 → data/*.json 갱신 (약 1분 30초)

mkdir -p _site && cp site/* _site/ && cp data/deals.json _site/
python3 -m http.server -d _site 8000
```
